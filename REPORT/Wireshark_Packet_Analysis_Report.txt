WIRESHARK PACKET ANALYSIS REPORT

Lab Title: Wireshark Packet Analysis


1. OBJECTIVE
The objective of this lab is to capture and analyze network packets using Wireshark in order to identify DNS traffic, TCP handshakes, HTTP communication, and any unusual or malformed packets.


2. TOOLS USED
- Wireshark (Windows)
- Command Prompt (nslookup, ping)
- Web Browser


3. GENERATING NETWORK TRAFFIC
Network traffic was generated using the following commands:

nslookup google.com
ping google.com

Additionally, HTTP traffic was generated by accessing:
http://example.com

This created DNS queries, TCP connections, and HTTP requests for analysis.


4. DNS ANALYSIS

Display filters used:
dns
dns.flags.response == 0
dns.flags.response == 1

Observations:
- DNS Server: 192.168.1.1
- Query: google.com
- Response IP Address: 142.251.223.14
- Both IPv4 and IPv6 addresses were returned
- Communication occurred over UDP port 53

The DNS request and response were successfully captured and analyzed.


5. TCP HANDSHAKE ANALYSIS

Display filter used:
tcp.flags.syn == 1

The TCP three-way handshake was observed as follows:

1. SYN (Client to Server)
2. SYN-ACK (Server to Client)
3. ACK (Client to Server)

The handshake established a successful TCP session between:
- Source IP: 192.168.1.104
- Destination IP: Remote Web Server

Sequence numbers and acknowledgment numbers were analyzed to understand the connection establishment process.


6. HTTP ANALYSIS

Display filter used:
http

An HTTP GET request was captured when accessing example.com.

Observations:
- GET / HTTP/1.1
- Destination Port: 80
- Server Response: 200 OK or 304 Not Modified
- Clear-text HTTP headers visible

This confirms successful HTTP communication.


7. SUSPICIOUS OR UNUSUAL TRAFFIC

Display filters used:
tcp.analysis.flags
quic

Observations:
- QUIC protocol traffic was observed
- No malformed packets detected
- No TCP retransmissions detected
- No reset attacks observed
- Network traffic appeared normal


8. CONCLUSION

The network traffic was successfully captured and analyzed using Wireshark.

The following were identified:
- DNS query and response process
- TCP three-way handshake
- HTTP GET request and response
- Encrypted traffic such as TLS and QUIC
- No suspicious or malformed packets detected

This lab demonstrated the fundamental concepts of packet analysis and protocol identification using Wireshark.
